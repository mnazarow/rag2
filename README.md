# Ассистент по корпоративной базе знаний — прототип

Отвечает в Telegram на вопросы по папке `BD`: каталоги, паспорта, сертификаты,
руководства, прайс-листы, регламенты 1С УТ и Битрикс24. Цитирует источники,
присылает файлы-первоисточники, собирает обратную связь и накапливает
выверенные экспертами ответы.

Прототип рассчитан на запуск за 10 минут без единого внешнего сервиса,
но собран так, чтобы каждый компонент менялся на промышленный аналог
(Qdrant вместо numpy, GigaChat/YandexGPT вместо заглушки, aiogram вместо
встроенного поллера) без переписывания остального кода.

## Быстрый старт

```bash
cd assistant
pip install -r requirements.txt          # минимум: httpx, numpy, openpyxl, python-docx
cp .env.example .env                     # укажите KB_ROOT — путь к папке BD
python index.py build --limit 200        # пробная индексация 200 файлов
python index.py stats
python index.py train-lsa                # смысловая модель на вашей же базе
python index.py reembed                  # пересчитать векторы под неё
python ask.py "какой напор у Водомет 55/75"
```

Шаги `train-lsa` и `reembed` обязательны: без них работает только поиск
по точным словам, и вопрос «какая производительность» не найдёт паспорт,
где написано «подача, м³/ч».

Полная индексация базы:

```bash
python index.py build                    # первый проход
python index.py update                   # потом — только изменившееся
python index.py watch --interval 300     # автоматическое обновление
python index.py repair                   # досчитать векторы, если индексация прервалась
python index.py reembed --provider onnx  # сменить модель поиска без переразбора файлов
```

Нетекстовые материалы и внешние источники:

```bash
python media.py cad                      # надписи с чертежей (из PDF-двойников и DXF)
python media.py transcribe               # расшифровка видео с таймкодами
python media.py describe                 # описания фотографий и надписи с шильдиков
python crawl.py urls                     # какие сайты упомянуты в базе ярлыками .url
python crawl.py sites                    # обойти сайты из crawl_sources.txt
python crawl.py search "вопрос" --index  # поиск в интернете с сохранением находок
```

Управление и проверка:

```bash
python audit.py report                   # аудит базы: дубли, сироты, пробелы, противоречия
python graph.py build --out graph.html   # граф связности, открывается в браузере
python webui.py                          # веб-интерфейс администратора на localhost:8800
python settings_schema.py md > НАСТРОЙКИ.md   # справочник по всем настройкам
```

Проверено на реальной базе (макбук, без GPU). В обработку попадают все
9 553 файла, а не только текстовые: чертежи, фотографии, видео и архивы
получают текстовую карточку и становятся находимыми. Дубликаты отсекаются
по хэшу содержимого, папки «Архив» помечаются неактуальными, большие книги
Excel (программы подбора с макросами) не вычитываются целиком.

Запуск бота:

```bash
# в .env: TELEGRAM_BOT_TOKEN, TELEGRAM_ALLOWED_IDS, TELEGRAM_ADMIN_IDS
python bot.py
```

## Ключевые решения и почему они такие

**Гибридный поиск, а не только эмбеддинги.** На запросах вида
`SPL WRP-A 2ECO6-38` или `арт. 500095.F` векторный поиск промахивается,
а BM25 попадает точно. На формулировках «чем отличается скважинный насос от
колодезного» — наоборот. Списки объединяются через Reciprocal Rank Fusion,
это отраслевой стандарт и не требует подбора весов.

**Цены не идут через векторный поиск.** Прайс-листы разбираются в обычную
таблицу, вопрос про цену роутится туда. Векторный поиск возвращает *похожие*
строки, а похожая цена — это неверная цена. Позиции из прайса подаются модели
отдельным блоком с пометкой «точные данные, приоритет над остальным».

**Контекстная приставка к чанку.** Фрагмент «Напор 45 м, расход 3,6 м³/ч» сам
по себе не находится ни по бренду, ни по модели. Поэтому к каждому чанку
дописывается строка вида «Фрагмент документа: Джилекс, паспорт, «Водомет 3ДК»,
раздел: Технические характеристики». Это дешёвый детерминированный вариант
Contextual Retrieval — работает всегда и без затрат на LLM. Полный вариант
(генерация контекста моделью) включается флагом `CONTEXTUAL_CHUNKS=1`.

**Приоритет свежести.** У документов извлекается дата из имени файла
(`price_300326`, `PRICE 01.02.2026`, `с 03-03-2026`). Если по одному
«ключу версии» есть несколько документов, старые помечаются
`is_current=0` и не попадают в выдачу — это решает проблему «в базе лежат
и старый, и новый прайс, бот отвечает по старому». Дополнительно в скоринге
работает мягкий бонус за свежесть.

**Честный отказ.** Ретривер всегда что-то возвращает, даже когда релевантного
в базе нет. Поэтому в промпте прямой запрет догадываться, а ниже порога
уверенности бот отвечает «в базе нет данных» и записывает вопрос в список
пробелов для экспертов.

**Роли.** Раздел базы виден не всем: дилерская продукция, розница, внутренние
регламенты 1С разграничены через `ROLE_SECTIONS` в `config.py`. Фильтр
применяется на уровне поиска, а не постобработки.

Важно: имена в `ROLE_SECTIONS` должны совпадать с именами папок первого уровня
внутри `KB_ROOT`. Если поменять `KB_ROOT` на подпапку, разделы станут другими и
роль отсечёт всю выдачу. `python index.py stats` подсказывает такие
несоответствия, а поиск пишет предупреждение в консоль.

## Как это «дообучается»

Четыре независимых контура, от самого дешёвого к самому дорогому:

1. **Новые файлы подхватываются сами.** `index.py watch` обходит папку, сверяет
   sha256 каждого файла и переиндексирует только изменённое. Удалённые файлы
   вычищаются сверкой. Переименование папки или пересинхронизация облака лишней
   работы не вызывают.

2. **Обратная связь от сотрудников.** Кнопки 👍/👎 под каждым ответом пишутся
   в таблицу `feedback`, а пары «вопрос → показанный фрагмент» копятся в
   `training_pairs`. 👎 уходит уведомлением экспертам.

3. **Выверенные ответы (главный механизм).** Эксперт пишет
   `/expert вопрос | ответ` — ответ попадает в таблицу `golden_qa` и с этого
   момента отдаётся на похожие вопросы приоритетно, минуя поиск. Это самый
   дешёвый способ «обучения» и он даёт наибольший эффект: бот перестаёт
   ошибаться там, где уже ошибся один раз.

4. **Дообучение эмбеддера и реранкера.** Когда в `training_pairs` накопится
   порядка нескольких тысяч подтверждённых пар, на них дообучается модель
   поиска (sentence-transformers, `MultipleNegativesRankingLoss`). По
   опубликованным замерам на ~4,7 тыс. пар это даёт около +6–7 % к NDCG@10 и
   стоит копейки. Дообучать саму LLM ради знания фактов не нужно — факты
   устаревают, их место в базе, а не в весах модели.

Пробелы в базе видны командой `/gaps`: вопросы, на которые бот не ответил или
получил 👎. Это готовый список задач на пополнение базы знаний.

## Сканы без текстового слоя

Примерно каждый пятый PDF в базе — скан без текстового слоя (в основном
сертификаты и декларации соответствия). Такие документы помечаются
`needs_ocr=1` и в поиск не попадают:

```bash
python ocr.py providers          # что доступно на этой машине
python ocr.py queue              # список документов, требующих распознавания
python ocr.py run --limit 20     # проба
python ocr.py run                # весь остаток
```

Отдельная забота — подмена кириллицы латиницей: у части распознавателей
«МОСКВА» превращается в «MOCKBA», текст выглядит верным, а документ
теряется навсегда. Проверка на такую подмену включена по умолчанию:
смешанные слова чинятся, целиком «латинские» сверяются со словарём вашей
же базы, а страницы, которые исправить нельзя, уходят запасному
распознавателю. Подробности — в разделе 5.4 документации.

## Замер качества

```bash
mkdir -p eval && cp eval/golden.example.jsonl eval/golden.jsonl   # и дополните своими
python evaluate.py --dataset eval/golden.jsonl --llm
python evaluate.py --dataset eval/golden.jsonl --compare   # сравнить настройки выдачи
python regression.py run                                   # прогон с сохранением в историю
python regression.py diff                                  # что изменилось после правки
```

Аналитика по накопленным вопросам:

```bash
python analytics.py funnel       # где теряются ответы
python analytics.py confidence   # каким должен быть порог отказа
python analytics.py channels     # нужна ли более сильная смысловая модель
python analytics.py gaps         # чего не хватает в базе знаний
python tracing.py show 42        # разбор конкретного ответа целиком
```

Автопроверки (работают на временных базах, рабочий индекс не трогают):

```bash
python tests/run.py
```

Эксплуатация:

```bash
python schedule.py install    # копии, проверки, очистка, учебное восстановление
python alerts.py list         # что сейчас требует внимания
python retention.py status    # что и сколько хранится
python runjob.py restore_drill  # развернуть копию и проверить, что поиск по ней работает
```

Без набора реальных вопросов сотрудников любые улучшения делаются вслепую.
Минимум — 50 вопросов, рабочий объём — 150–300.

## Переход в продакшен

| Прототип | Продакшен |
|---|---|
| numpy-индекс в файле | Qdrant (гибридный поиск и фильтры из коробки) |
| `EMBEDDINGS_PROVIDER=lsa` (своя модель) | `onnx` с USER-bge-m3 либо `gigachat` |
| `LLM_PROVIDER=echo` | `local` (своя модель) с `LLM_FALLBACK=gigachat` |
| `RERANKER_PROVIDER=lexical` | `onnx` с BGE-reranker-v2-m3 |
| копии индекса вручную | `backup.py schedule` + `BACKUP_MIRROR_DIR` |
| встроенный поллер | aiogram (ставится из requirements) |
| логи в SQLite | Langfuse для трассировки и разметки |

Режим `hashing` существует ровно для одного: запустить конвейер на пустой
машине и убедиться, что он работает. Смысловой близости он не даёт —
поиск в нём держится на одном BM25, и в работе его использовать нельзя.
Значение по умолчанию — `lsa`: модель обучается на вашей же базе за
минуты, ничего не скачивает и даёт настоящий смысловой канал.
